# nano_j2me 0.5.24

0.5.24 adds real rendering for Nokia's overlay-item API: `CanvasGraphicsItem`
subclasses attached to a `Canvas` are now composited on top of the canvas after
its `paint()` runs, instead of being invisible as in the reference emulator.

## Highlights

* **Nokia `CanvasItem` / `CanvasGraphicsItem` overlays** (`src/midp/nj_lib_nokia.c`,
  `src/midp/nj_lib_lcdui.c`): `CanvasItem` carries the parent/size/position/
  visibility/z state; `CanvasGraphicsItem` validates its `(int, int)` size,
  validates that `setParent()` receives a `Canvas`, rejects a negative z
  position, and dispatches the abstract `paint(Graphics)` virtually. The list
  of attached items is a lazy package-private `cItems` Vector field on the
  `Canvas` builtin, so the GC sees the items; after the canvas paint the runtime
  translates and clips a Graphics onto the canvas backing image per visible
  item and invokes its paint. An exception in an item's paint clears and stops
  the overlay pass instead of aborting the frame.
* Verified end-to-end: `tests/canvasitemdemo/CanvasItemDemo.java` paints a blue
  canvas with a green 40x30 item at (10,20); `tools/check_canvasitem.sh` dumps
  the frame and asserts green inside the item rectangle and blue everywhere
  around it, plus the Java-visible parent/position/size and both documented
  `IllegalArgumentException` paths. This is `test_canvasitem`, and the fixture
  is generated by `nj_fixtures`.
* Android releases keep shipping per-architecture APKs (`arm64-v8a`,
  `armeabi-v7a`, `x86`, `x86_64`, plus the ARMv5 `legacy` build).

## Upgrade notes

Save states created by 0.5.8 through 0.5.23 are refused by the 0.5.24 core
(state format version CRC), as before; export/import through in-game saves or
start a fresh state. The cheat engine, SYSTEM_RAM memory map, multi-touch
pointer reporting and per-ABI APK packaging are unchanged.
