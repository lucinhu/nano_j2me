# H.263 and MPEG-4 numeric table provenance

This record covers reproducible numeric inputs for the H.263 and MPEG-4 tables. H.263 uses the pinned ITU publication below. MPEG-4 intra/DC/scale data are regenerated from a pinned MIT-licensed OxideAV source, with the original copyright and permission notice retained. Decoder algorithm provenance and the wider codec audit are separate from this table record; consult `docs/CODEC_PROVENANCE.md` for their current status.

## H.263 source and reproducible extraction

The numeric input is [ITU-T H.263 (01/2005), Video coding for low bit rate communication](https://www.itu.int/rec/T-REC-H.263-200501-I/en), approved 2005-01-13. The official English publication is available through [ITU's PDF link](https://www.itu.int/rec/dologin_pub.asp?lang=e&id=T-REC-H.263-200501-I!!PDF-E&type=items).

The exact publication inspected is 1,900,840 bytes, with SHA-256:

```text
9dc7e2528fa13ac9d3b6669996b053f6cea7897b5e1ecdd46a253e858ffd2c45
```

The PDF remains a separately downloaded standards document, outside the runtime and tracked source data. `tools/data/h263-vlc-2005.json` records only numeric coding events and bitstrings, retaining the source table row identifiers. `tools/gen_h263_tables.py` contains the extraction and rendering implementation under MIT. It accepts no external decoder source as an input.

| Normative source | Stored facts | Generated use |
| --- | --- | --- |
| Table 2, printed p. 7 | Standard picture dimensions | Standalone H.263 width and height arrays |
| Table 7, printed p. 34 | Intra MCBPC codewords and macroblock types | Shared and standalone MCBPC arrays |
| Table 8, printed p. 34 | Inter MCBPC codewords and macroblock types | Shared and standalone MCBPC arrays |
| Table 12, printed p. 37 | CBPY codewords | Shared and standalone CBPY arrays |
| Table 13, printed p. 38 | DQUANT codewords and differential quantizers | Standalone H.263 quantizer deltas |
| Table 14, printed pp. 38–40 | Signed half-sample motion-vector codewords | Unsigned-magnitude VLC prefixes, with sign consumed separately |
| Table 16, printed pp. 41–44 | LAST, RUN, magnitude and VLC codeword; escape codeword | Shared inter coefficient events, standalone H.263 coefficient events, packed RUN/LEVEL arrays |
| Figure 14, printed p. 47 | One-based coefficient position at each matrix location | Standalone H.263 zigzag array |

The shared macroblock codeword arrays are in `src/midp/nj_vlc_intra.h`; shared inter coefficient data are in `src/midp/nj_vlc_inter.h`. The standalone arrays are in `src/midp/nj_h263.c`.

The generator maps published macroblock types to the decoder's established flag representation (intra 4, quantizer change 8, four-vector prediction 16), keeps three unused zero-length slots in the shared inter array, and maps published motion displacements to magnitude prefixes. It removes only the explicitly separate coefficient sign bit from the published codeword widths.

The 4,096-entry inter lookup is generated by enumerating every 12-bit lookahead and selecting its unique codeword prefix; unassigned and escape lookaheads use `0xffff`. Escape boundary arrays are maxima over the represented `(LAST, RUN, magnitude)` event sets. No decoder's table-initialization routine is used. Checks cover prefix uniqueness, every lookahead, event counts, published row indices and byte-for-byte regeneration.

Reproduce from the repository root after downloading the pinned publication:

```sh
python3 tools/gen_h263_tables.py --extract /path/to/h263-2005.pdf --check
python3 tools/gen_h263_tables.py --check
```

The first command requires `pdftotext` with layout output support. Both reject stale generated files; the extraction command also rejects a different PDF hash and checks the canonical numeric input. Omitting `--check` regenerates the data and headers. Normal builds use checked-in numeric data and do not download a standard or run a Python generator.

All 20 pre-existing numeric arrays across these three source files were compared with their values before regeneration and remained equal. Regeneration supplies a traceable source and reproducible construction while preserving decoding behavior. It does not audit unrelated function implementations in those files.

## MPEG-4 tables from pinned MIT OxideAV source

The replacement input is [OxideAV/oxideav-mpeg4video](https://github.com/OxideAV/oxideav-mpeg4video/tree/ebfef14e48acf63547f73a9a0f4c36a153db92b2), revision `ebfef14e48acf63547f73a9a0f4c36a153db92b2` (Cargo version 0.1.10). Its actual [LICENSE at that revision](https://github.com/OxideAV/oxideav-mpeg4video/blob/ebfef14e48acf63547f73a9a0f4c36a153db92b2/LICENSE) grants MIT, copyright (c) 2026 Karpelès Lab Inc. The complete grant and copyright are retained in `docs/licenses/third-party-code-MIT.txt`, which accompanies each locally packaged binary.

The consumed files were inspected directly, including their table meanings and attribution comments. Upstream states these tables were reconstructed from ISO/IEC 14496-2:2004, without consulting third-party MPEG-4 source. That statement is recorded as upstream provenance; the local reconstruction uses the explicitly MIT-licensed source, not an unverified local copy of the ISO publication. No Rust package or executable is introduced into the build.

| Pinned source | Numeric input | Generated use |
| --- | --- | --- |
| `src/texture.rs`, `DC_SIZE_LUMINANCE` / `DC_SIZE_CHROMINANCE` | 13 codewords and decoded sizes per component; upstream identifies Tables B.13/B.14 | Both DC-size arrays |
| `src/tcoef_tables.rs`, `TCOEF_INTRA` | 102 `(code, length, LAST, RUN, magnitude)` entries; upstream identifies Table B.16 | Intra RUN/magnitude arrays and all 4,096 prefix lookup entries |
| `src/predictor.rs`, `dc_scaler` | Piecewise integer expressions; upstream identifies Table 7-1 | Luminance/chrominance scaling arrays for valid quantizers 1..31 |

Every consumed upstream file is pinned by SHA-256:

```text

src/texture.rs       fa6981a1cd44bd2dd56378c2e33c19964d235eeac0ccee37eba82054c09a52d1
src/tcoef_tables.rs  9c1279b6c4c7edba0163570ae448a41d9ad623cf176ee506656fb98511985912
src/predictor.rs     48d349cd55d0828aadad416dc8d4e4c32ac9298791deae14a930d6df997003fd
```

`tools/gen_m4v_tables.py` checks those hashes before extraction and records the numeric inputs and scaling expressions in `tools/data/m4v-oxideav-tables.json`. Codewords are retained as bitstrings. The generator sorts the intra events by `(LAST, RUN, magnitude)` for the existing decoder representation, then builds its lookup by direct prefix enumeration and independently checks every entry by string-prefix matching. It also validates DC-size coverage, codeword prefix uniqueness including the escape codeword, event meanings, the 67/35 LAST split, and scaling-rule coverage. Scaling index zero is a local unused sentinel; upstream accepts only positive quantizers.

`tools/gen_m4v_escape.py` computes maxima of the represented event sets to generate the four escape boundary arrays. It reads the regenerated project event header; it neither parses an FFmpeg header nor uses an external decoder's table-initialization routine.

Reproduce from a local read-only checkout of the pinned revision:

```sh
python3 tools/gen_m4v_tables.py --extract /path/to/oxideav-mpeg4video --check
python3 tools/gen_m4v_tables.py --check
python3 tools/gen_m4v_escape.py --check
```

Omit `--check` to regenerate. The extraction check verifies both the pinned upstream input and the checked-in canonical JSON. Normal builds use checked-in headers; they perform no downloads and require neither Python nor Rust.

All seven numeric arrays in `include/nj2me/nj_m4v_tables.h` were compared before and after this source replacement and remained identical, including every lookup entry. All four escape boundary arrays also retain their values. Focused `test_m4v` and `test_h263` both passed after regeneration. No upstream table correction was required for these inputs. Earlier FFmpeg-derived headers are historical source, not the input to the replacement generator. This table replacement does not audit function implementations elsewhere in the MPEG-4 provider.

## Scope of the evidence

The new Python generator implementations are project code licensed under MIT. The MPEG-4 inputs retain OxideAV's MIT copyright and permission notice. The ITU and ISO publications retain their own copyright and access terms; this document does not relicense either publication. The extracted H.263 rows record numerical codeword facts needed for interoperable decoding. A reproducible source trail is evidence for review, not a legal clearance certificate or a formal clean-room claim: earlier project source containing FFmpeg-derived arrays was inspected during the audit. Numeric equality alone also cannot establish the absence of copied expressive source code elsewhere in the decoder.
