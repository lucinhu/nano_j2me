# 四采样抗锯齿、JIT 探测与 Vulkan RGB565 · 2026-11-26

基线为 `d067109df3a4a8d5522dac75625e97bfb1d178ad`。桌面计时使用 Intel Core Ultra 9 275HX、Linux x86-64、GCC 16.2.1 和 Release 构建。各组在同一 CPU 核上交替运行两版，表中给出耗时中位数。[上一轮测量](2026-11-26-smooth-jit-upload.md)

## 纯软件四采样抗锯齿

《田园物语》以 2× 内部倍率、原始像素和四采样运行时，帧末的四采样合成占 `gprof` 采样的 41.3%。现在合成循环预先读取输出宽度，让编译器能并行处理多个像素。遇到相同的上下两行时，只需计算水平方向两点的均值。遇到与上一组完全一致的两行时，可以直接复制上一行结果。两条捷径都先比较末尾像素，再检查整行。RGBA 的每个通道都保留 `(四个样本之和 + 2) / 4` 的整数舍入。[实现](../../src/midp/nj_hd_surfaces.c) · [像素回归](../../tests/test_hd_surfaces.c)

固定 CPU 2，只替换基线软件库中的四采样合成模块。两款游戏均使用 240×320 逻辑画面、`--render-scale 2 --ssaa 2`、固定游戏时钟和相同按键。原始像素取五对，其余模式取三对。计时从启动到退出，关闭截图。另行回放，每 90 帧比较一张完整的 480×640 画面。[游戏校验值、按键与固定时钟](2026-11-26-smooth-jit-upload.md#纯软件高清渲染)

| 素材采样 | 《田园物语》1,080 帧 | 耗时降低 | 《我的机器女友》900 帧 | 耗时降低 |
| --- | ---: | ---: | ---: | ---: |
| 原始像素 | 1.631 → 1.398 s | 14.3% | 1.401 → 1.198 s | 14.5% |
| 像素画清晰 | 2.941 → 2.739 s | 6.9% | 1.842 → 1.648 s | 10.5% |
| 柔和平滑 | 6.067 → 5.886 s | 3.0% | 3.622 → 3.508 s | 3.1% |

六组共 66 张取样帧逐字节吻合。固定 CPU 10 单独测量 480×640 输出的合成步骤，每轮预热 12 帧，计时 360 帧，交替运行五对。随机像素从 412.9 降到 158.7 微秒，重复行从 411.8 降到 124.6 微秒。相邻行只在倒数第二个像素不同时从 413.1 降到 212.8 微秒。回归测试另用独立的逐通道公式穷举两样本的 65,536 组字节组合，并覆盖四个样本独立变化、奇数输出宽度和帧间写入。

## 虚拟机执行

将 JIT 探测集中到可进入原生代码的字节码边界。普通指令直接分派下一条指令，分支出口、方法切换和异常恢复仍在相应位置检查。x86-64 Release 中，编入 JIT 的 `nj_interp_run` 机器码从 170,730 字节降到 101,161 字节。[分派实现](../../src/core/nj_interp.c)

固定 CPU 4，运行原版 MinecraftJ2ME PE 0.6.1 的 `Gen.generate`，种子 `12345`，每次启动新 VM 并生成 256 个区块。每种配置各取三对。第一、二行使用同一种编入 JIT 的构建，第三行单独编译。[基准与链接命令](../../tools/bench_minecraft_gen.c)

| 编译配置和运行模式 | 基线 | 本轮 | 耗时降低 |
| --- | ---: | ---: | ---: |
| `NJ_ENABLE_JIT=1`，解释执行 | 14.538 s | 12.544 s | 13.72% |
| `NJ_ENABLE_JIT=1`，JIT 执行 | 12.049 s | 11.481 s | 4.71% |
| `NJ_ENABLE_JIT=0`，解释执行 | 9.152 s | 9.141 s | 0.12%，处于波动范围 |

```sh
taskset -c 4 bench_minecraft_gen original.jar 12345 --jit-mode interpreter
taskset -c 4 bench_minecraft_gen original.jar 12345 --jit-mode execute
```

18 次运行的 256 对区块哈希逐一吻合，世界摘要为 `a893a062 / c77a1b93`，出生点为 `(161, 64, 111)`。两版在 JIT 执行模式下都编译了 235,949 个代码块，原生执行了 4,846,453,354 条 Java 字节码。线程化分派、可移植 `switch` 分派和纯解释器构建各有 27 项计算摘要与桌面 JVM 一致。

## Vulkan RGB565

提交采用 RGB565 画面的绘图包时，按行将源像素转换到 Vulkan 暂存缓冲区，绘制完成后再逐行读回。固定宽度的转换支持未对齐的地址和有填充的行。回归逐字节核对裁剪范围内外的颜色、行尾填充和独立的深度缓冲区。[转换实现](../../src/port/vulkan/tri_draw.inc) · [基准和正确性检查](../../tests/test_gfx_vulkan.c)

固定 CPU 8，计时范围包含上传、绘制、等待 GPU 完成和读回。计时用例每次从相同地址读取刚改写的颜色，关闭深度写入。短测每轮预热 5 次、计时 51 次，五轮取中位数。240×320 另做长测，每轮预热 31 次、计时 401 次，按 ABBA 和 BAAB 交替六组，每个版本共 12 轮。

| GPU 与裁剪区 | 基线 | 本轮 | 耗时降低 |
| --- | ---: | ---: | ---: |
| RTX 5080 Laptop，240×320，长测 | 0.1635 ms | 0.1160 ms | 29.1% |
| Intel ARL，240×320，长测 | 0.3875 ms | 0.3390 ms | 12.5% |
| RTX 5080 Laptop，1280×720，短测 | 2.107 ms | 1.736 ms | 17.6% |
| Intel ARL，1280×720，短测 | 3.670 ms | 3.438 ms | 6.3% |

Intel 的 240×320 短测为 0.340 → 0.385 ms，耗时增加 13.2%。延长采样后，旧版 12 轮的中位数范围是 0.366–0.407 ms，新版是 0.319–0.363 ms，六组内新版均较快。复现短测可在开启 Vulkan 的构建中执行下列命令。长测使用同一测试，仅对小尺寸用例调整预热与计时次数。

```sh
VK_DRIVER_FILES=/usr/share/vulkan/icd.d/intel_icd.json taskset -c 8 build/test_gfx_vulkan --bench-rgb565
VK_DRIVER_FILES=/usr/share/vulkan/icd.d/nvidia_icd.json taskset -c 8 build/test_gfx_vulkan --bench-rgb565
```

## 集成验证

纯软件 Release 通过 222/222 项测试，编入 JIT、GLES2、Vulkan 和 FSR2 的 Release 通过 236/236 项。四采样合成测试通过 AddressSanitizer 和 UndefinedBehaviorSanitizer。两块 GPU 上的 Vulkan 回归也通过 Clang 的 UndefinedBehaviorSanitizer 检查。

用完整构建重放上述两款游戏与三档素材采样，纯解释器和 x86-64 JIT 各有 66 张画面与基线逐字节吻合。JIT 在两款游戏中分别原生执行了 48,466,374 和 59,656,916 条 Java 字节码。另在 RTX 5080 Laptop 上以 2× 内部倍率运行《毁灭战士3》250 帧，GLES2 和 Vulkan 各自的 31 张取样画面、9,873 个绘图包和 4,229,899 个提交三角形均与对应的基线吻合。

Android 9+ arm64 试用包以 `NJ_ANDROID_JIT=1` 构建。在 API 36 的 x86-64 模拟器上通过 arm64 转译运行，覆盖安装后用原始像素、2× 内部倍率、四采样启动同一个 MIDlet。两版素材区域的 SHA-256 均为 `d425390819778aded89256d1fa9a6444e5bb642e10e30acb3e480a295f904e31`。试用包已通过 APK v3 签名校验，SHA-256 为 `66e2caee3f8f4f19f4750fae8f956c546bfd121397a24b8968d61345c23bd180`。
