## 结论

**回合不推进。** 顶栏右上角的「回合: N」在教程战役地图上恒为 **0**。

判定方式：把窗口像素 `(786,68)` 起 `30x45` 的区域（正好框住数字「0」）取像素 md5，
**全部 78 张截图、全部输入组合下该值恒为 `4c2d290ab6b7`**，即回合数从未变化。

**为什么（应用侧 / 输入通道限制，不是模拟器缺陷）**：

1. 顶栏显示的回合数就是 `g.bl`（int）。全类**只有一处**会推进它：`g.ae()`（g.java:9707）里的
   `bl += n2`。javap 硬证据见 §证据。
2. `ae()` 全类**只有两个调用点**：
   - g.java:6101 —— 右软键（按键索引 19）经 `g.g(29,19,true)` 触发 widget 组 29 的动作，
     当 `f.j == 8` 时调用 `g.aq(); g.ao(); g.aG(); g.ae();`；
   - g.java:6392 —— 玩家结算阶段 `case 2: { if (g.r(g.O)) break; g.r(0,0); g.ae(); }`，
     即**"该玩家所有单位的 AP / 移动力都耗尽且没有待执行命令"时自动结束回合**。
3. 右软键这条路被 `g.p(18)` 门控（按钮 18 的状态必须 ∈ {4,6,10}）。而按钮 18 的状态由
   `g.af()`（g.java:9873，字节码见 §证据）计算，**第一个分支就是**
   「是我的回合(`O == N`) 且 `g.V <= 0` → 状态 0 = 禁用」。
   `g.V`（int，javap 字段 `#353`）全类**只有两处写**：
   `g.java:5400 g.V = 0;`（战斗初始化）与 `g.java:15355 V = g.b();`（读存档）。
   新开局没有存档 ⇒ **V 恒为 0** ⇒ 按钮 18 恒为禁用 ⇒ `g.p(18)` 恒假
   ⇒ 右软键永远到不了 `f.j == 8`。
4. 于是唯一能推进回合的实际路径是第 2 条（AP 耗尽自动结算），它要求玩家**真的把单位的
   AP 花光**。移动指令入口在 g.java:5866：
   `if (g.a != null && g.V == 0) { … case 1: … g.d(g.dc, g.dd, g.a); … }`，
   前提是 `m.f(5)`（FIRE 在被轮询的那一帧正好是"按下沿"）、`g.am` 为真、且目的格
   `(g.dc,g.dd)` 不是单位自身所在格。实测教程教的「5 选定 → 移光标 → 再 5 确定」序列
   **没有产生任何指令**（见 §复现步骤）；更关键的是 g.java:5750-5793 的选中逻辑表明
   **未按 5 时代码会自动选中第一个可见单位，按 5 反而是"取消选中"**，
   所以教程文案的"5"与我们看到的现象并不一致。
5. 以上还叠加了游戏自身的**按键闩锁缺陷**（m.java）：
   `keyReleased` 把 `b[i]` 置负，而 `paint` 对负值只清 `m.b[i]`、**永不清 `b[i]`**，
   `keyPressed` 又只做 `b[i]++` ⇒ 同一个键**每 3 次按压只有 1 次对游戏可见**。
   这解释了"按了没反应"的大多数现象（也解释了我们必须每个键连按 3~4 次）。

**指针通道是诚实的**：XTEST 鼠标与 uinput 虚拟触屏**两条**通道都把 MIDP 的
`pointerPressed`/`pointerReleased`（`kind=1/0`）真实送到了游戏类 `g`
（run3 日志共 **112 条 NJPTR**），坐标与窗口→游戏坐标映射完全一致；
唯一生效的指针交互是"点击移民 → 单位出现黄色选中环"。游戏对这些点击/长按**一律不响应**，
因此问题在游戏侧的命中/状态机，不在模拟器。

## 边界与未验证项

1. **没有用 HEAD 干净构建复跑**。`.local-tools/head-build-20261022/build/nj2me`
   （SHA-256 `9f6325a7…`）在本机启动后日志停在
   `INFO: thrown: java/lang/NullPointerException at j.d()V pc=859: (no message)` 之后
   （没出现 MediaException / audio 行），**SDL 窗口始终没有创建**
   （`xdotool search --pid <pid>` 无结果；主线程 `wchan=hrtimer_nanosleep`、State S、2 线程）。
   试过 `SDL_AUDIODRIVER=dummy`、`NJ_SDL_GRAB=1`、换新 `--rms-dir` 均无效。
   因此本轮取证全部使用 nfs-cam 快照构建（SHA-256 `7429b5e2…`），它比 HEAD 旧，
   差异是 `NJ_MOUSE`/`NJ_PTR` 日志与当时的音频后端；**Lead 提到的 `nj_interp.c`
   "无类数组按 Object 派发"与 `nj_lib_string.c` "空串 UB 修复"两处在本轮二进制里不存在**，
   但它们不涉及输入/回合逻辑。**这是本轮结论最主要的未闭合项。**
2. **没有观测到运行时 `g.O` / `g.N` / `g.V` 的实际值**（不能改 `src/` 插桩）。
   "按钮 18 恒禁用"是由字节码（`V:I` 只有两处写 + `af()` 的分支顺序）推出的**静态结论**，
   与实测（右软键怎么按都不推进）一致，但缺少运行期数值直接佐证。
3. **没有让任何单位真正移动过**，所以"AP 耗尽 → 自动结束回合"这条路径**没有走到终点**。
   已知能改游戏状态的指针交互只有"点单位 → 选中环"；教程的 5/5 指令序列没有触发。
4. 只覆盖了**教程第一张战役地图**（公元前 4000 年）。非教程局、后续回合、
   以及"完成序幕剧情进入正式战役"的另一条路径没有复测。
5. **XTEST 指针在本会话是好的**（有 NJPTR 证据，点击移民真的生效），
   与 Lead 实测的"xdotool 鼠标事件在本机是死的"**不一致**；两者是不同会话/不同 DISPLAY 状态，
   报告里两者并列记录，不做取舍。
6. uinput 虚拟触屏必须**在模拟器启动之前**就已注册（SDL2 只在进程启动时枚举 `/dev/input`，
   之后热插拔的 uinput 节点不会被认领）——本轮靠常驻 `vptr2`（设备 `nano_vtouch2`）
   达成；`.local-tools/debug-runs/pointer-20261022/vptr` 每次运行只存活约 0.7 s，
   在模拟器启动后才建设备则**永远送不进事件**（此前 5 次尝试全部无 NJPTR）。
7. 本轮**没有改动** `src/`、`include/`、`tests/`、`CMakeLists.txt`，**没有动 git 状态**，
   没有修改原 JAR，也没有碰其它 agent 的 run 目录（曾误用 `xdotool search --pid`
   抓到别的会话窗口，已核对 `xdotool getwindowpid` 后作废并删除那批截图）。
8. 若要继续推进，**唯一有希望的模拟器侧改动**是"按键闩锁"以外的**事件时序**问题：
   目前模拟器把 SDL 的 `KEYDOWN`/`KEYUP` 直接转成 MIDP `keyPressed`/`keyReleased`，
   而游戏在 `paint` 里**每帧只采样一次**按键状态；`xdotool key` 的 12 ms 按压会整帧丢失。
   这属于**游戏侧**的采样模型缺陷，**不建议**在模拟器里改（会改变所有游戏的按键语义），
   记录在此供后续决策。
