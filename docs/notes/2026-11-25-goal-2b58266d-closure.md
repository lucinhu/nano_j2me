# 目标 goal-2b58266d 收尾记录（2026-11-25）

三项长期改进的最终状态、证据与遗留项，按用户确认的决策记录。

## (1) GLES2 结构性改造 — 按决定停止实施，保留实验代码与完整测量

* 交付：B1（frame-resident 2D 层，`d2b079b`）、B1.5（跨帧保持 GL 上下文，`b75a038`），
  均为 opt-in 实验代码（`NJ_SDL2_GLES2_FRAME=1` / `NJ_SDL2_GLES2_HOLD=1`，另有
  `NJ_SDL2_GLES2_2D=1`），默认不启用；像素一致性已用 LoopDemo / 浴火银河 2 逐帧
  PPM 对比验证为 0 差异。
* 测量与结论：`docs/notes/2026-11-24-gles2-frame-resident-2d-layer.md`、`…-b2-plan.md`、
  `…-b2-m1-classification.md`、`…-b2-m2-implementation.md`。关键数据：真实 GPU 上
  浴火银河 2 软件 5.01 s vs GL 6.01 s（跳过回读仍 5.55 s），毁灭战士 3 2.10 vs 2.69 s；
  M2 上限实验（`174e948`）显示即使合并 clear 也只剩 6.2–6.6 s，仍慢于软件。
* 用户决策：停止 B2 实施（`8518632`），软件渲染保持默认；未来唯一现实路线是
  M2.5 持久顶点/深度缓冲 + 真实深度 + EGL 呈现，最多打平。

## (2) TheMummy 事件线程模型 — 完成并发布

* `af81df1`：`java.util.Timer` 的 TimerTask 改为 Java 字节码调度（`pump()/afterRun()`），
  调度器可在量子边界抢占宿主游戏循环，20 ms 握手定时器不再被饿死；`in_timer_cb`
  语义 + `serviceRepaints` 节奏控制。
* 证据：CLI 600 帧 `frames=600 paints=609 gfx=11,610`，帧 300–600 非黑像素
  34,897/36,608；libretro core `PASS 47/0`、`frames_with_content=297/317`、存档可用；
  全语料探针 1,659/1,664（TheMummy 不再在失败列表）；完整 CTest 210/210。
* 随 v0.5.41/r60 发布。

## (3) 画面呈现增强 — 已交付可交付部分，GLES2 shader 管线随 B2 决定挂起

* 加速倍率：Android + SDL2 上限 4×→8×（`c60a815`）；运行时/存档本就支持 10–800%。
* 独立 SDL2 版呈现滤镜：最近邻/线性/扫描线/LCD 网格/CRT，设置项 `filter_mode`
  （兼容旧 `filter_linear`），验证基准帧 0 差异、扫描线 34.7%、CRT 53.9% 像素差异，
  `docs/UPSCALING.md`（`9b3e43c`）。
* libretro 侧：RetroArch 推荐 shader 预设表（2D 像素/整数缩放/CRT/LCD/FSR/混合），
  `docs/UPSCALING.md` §1（`eb5a84c`）。
* 未交付：GLES2/FSR 的实时后处理 shader 管线依赖窗口 EGL 呈现（B3），随 (1) 停止；
  Android 版滤镜 UI 同理挂起。记录为后续候选，不阻塞本目标。
