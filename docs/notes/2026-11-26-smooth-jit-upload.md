## JIT

Minecraft 世界生成中的噪声函数用条件表达式选择梯度。x86-64 和 AArch64 的扫描器原先把 `goto` 后面紧邻的指令当作可从上一行抵达，导致两个实际分支的操作数栈深度被误判为冲突。现在扫描器只合并可达路径，检查所有实际入边的栈深一致，并为可能抛出异常的指令记录该路径的栈深和已完成指令数。两个架构共用回归样例，覆盖两条分支、跨越死代码、栈深冲突、窗口末端和空引用异常。

使用原版 MinecraftJ2ME PE 0.6.1 的 `Gen.generate`，种子 `12345`，每次启动一个新的 64 MiB 虚拟机并生成 256 个区块。固定 x86-64 CPU 4，交替运行三对。

| 指标 | 基线 JIT | 本轮 JIT |
| --- | ---: | ---: |
| 生成耗时中位数 | 14.374 s | 11.642 s（降低 19.0%） |
| 原生执行的 Java 字节码 | 3,428,581,102 | 4,846,453,354 |
| 成功编译的代码块 | 180,847 | 235,949 |
| JIT 因保护检查退出的次数 | 0 | 0 |

另用同一个新版程序固定在 x86-64 CPU 2，分别启用 JIT 和解释器，交替运行三对。生成耗时中位数为 JIT 11.637 秒、解释器 14.350 秒，JIT 少用 18.9%。六次运行的每一对区块哈希都相同。

同样的 Java 程序和种子在 QEMU AArch64 上完整执行了一对。基线耗时 295.010 秒，新版耗时 221.169 秒，原生执行的 Java 字节码从 3,450,942,089 增至 4,880,215,203。两次均通过所有区块校验。此处计时包含 QEMU 的指令转译开销。

每个 JIT 版本均执行了 7,885,973,861 条 Java 字节码。基线 JIT、新版 JIT 和解释器的 256 对区块哈希逐一吻合，世界汇总为 `a893a062 / c77a1b93`，出生点为 `(161, 64, 111)`。

## GLES2

GLES2 按源格式转换每一行。RGB565 展开为 8 位通道，RGB888 连续取三个字节，ARGB8888 在转换一行时同时检查透明度。对于由游戏提供的像素内存，每次绘制都读取最新内容。

在 RTX 5080 Laptop（驱动 620.73.04）上运行 `test_gfx_gles2 --bench-blit`，固定 CPU 8。每轮预热 16 次，计时 256 次 480×640 同步上传、绘制和 ARGB8888 读回。基准使用裁剪过的未对齐源和带填充的行，每次修改一个采样点，检查该点和最后一帧的所有像素。下表取五对交替运行的中位数。

| 源格式 | 基线 | 本轮 | 耗时降低 |
| --- | ---: | ---: | ---: |
| RGB565 | 331 ms | 216 ms | 34.7% |
| RGB888 | 225 ms | 138 ms | 38.7% |
| ARGB8888 | 189 ms | 149 ms | 21.2% |

同一块 GPU 的 GLES2 一致性测试在两版上各通过 2,571 次画面比较。另在 GLES2、Vulkan 分别以 2× 内部倍率回放原版《毁灭战士3》250 帧，每个后端的 9,873 个绘图包和 4,229,899 个提交三角形均与各自基线吻合，两个后端各有 31 张取样画面逐字节一致。

## 构建与 Android 验证

纯软件 Release 通过 222/222 项测试，开启 JIT、GLES2、Vulkan、FSR2 的 Release 通过 236/236 项。高清绘图的独立测试同时通过 AddressSanitizer 和 UndefinedBehaviorSanitizer 检查。
