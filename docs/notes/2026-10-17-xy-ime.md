# 侠义 OL 自绘注册框无法打开编辑窗（2026-10-17）

## 原始复现与定位

- 基线：`89583cf`；原始 JAR：`/home/lucinhu/Downloads/jar/侠义OL-八龙聚首_诺基亚 N97系列(360×640)-871204.jar`。
- SHA-256：`bfa87c2046aa0d2b3847521ffdd34baf27a3de252b07031830d3b966eb2e66d2`。
- 真机 `425610ca`（marble）已安装包版本为 versionCode 10 / versionName 0.1.0，更新时间 2026-10-17 13:46:05。打开游客注册、同意协议后，点击账号、密码和手机灰框不出现输入法。未输入或提交账号，没有操作注册服务器。
- 屏幕 1080×2400；360×640 游戏区域约 x=180..900、y=60..1340。账号框内触摸约为游戏坐标 (117,44)。350ms 触摸也未能打开编辑窗口。检查输入法状态，`mInputShown=false`，served view 为 Activity DecorView。随后 ADB 设备列表变空。
- 桌面 headless 原版在相同注册页面也能复现：确认键 `fire`、数字 `5` 及框内触摸均不能进入编辑 Form，排除只在 Android 展示键盘时发生的问题。

游戏使用 Canvas 自绘的 `d` 超链接控件，灰框由 `<输入文字>` 标记生成；空框本身是游戏设计，不能据此判断中文丢失。输入链为 `w.pointerPressed/Released` → `d` 链接命中 → `Tribe.a(g).keyPressed(-5)` → `ak.a(d)` → `u.a(int,u)` 构建 Form。

`u.a` 在 pc1156 调用 setTitle 后，从 pc1165 开始对 11 个静态 Command 调用 removeCommand，再执行 deleteAll、append TextField、setCurrent。部分 Command 尚为 null。模拟器对 `Displayable.removeCommand(null)` 错误抛出 `NullPointerException: command is null`，被游戏工作线程捕获，截断了编辑 Form 的构造，因此系统输入法尚未得到激活机会。

MIDP API 规定 removeCommand 在参数为 null 或命令未添加时不产生效果；addCommand(null) 仍应抛异常。规范：[Displayable.removeCommand](https://docs.oracle.com/javame/config/cldc/ref-impl/midp2.0/jsr118/javax/microedition/lcdui/Displayable.html#removeCommand(javax.microedition.lcdui.Command))。

## 修复与实际验证（2026-10-19）

修复位于 `src/midp/nj_lib_lcdui.c`，没有为该游戏添加专用分支：

1. `Displayable.removeCommand(null)` 和移除未添加命令成为无操作；`StringItem` 只清除与参数相同的非空默认命令；`addCommand(null)` 仍抛 NPE。
2. `TextField.setMaxSize` / `TextBox.setMaxSize` 的注册描述符由错误的 `(I)V` 改为 `(I)I`，返回实际最大长度。游戏在构造编辑 Form 时调用这两个 API，之前会因方法解析失败截断流程。
3. 内建 Form/TextBox 等屏幕共用 `screen_commands()` 选择和绘制软键：正向命令分配左键，BACK/CANCEL/STOP/EXIT 分配右键；组内按 priority 和原有类型顺序选择。仅有一个命令时双键都能触发它。SOFT2 不再作为默认 fire；Canvas 的独立命令路径保持原样。

第三项解释了第一轮能编辑却返回空账号的问题。游戏 `u` 先添加确认 `type4, priority1`，再添加返回 `type3, priority1`；旧默认选择在相同 priority 下选较小类型，因此选择了返回。`u.commandAction` 只有 type4 的注册/登录分支（状态191/192，pc488–530）读取 TextField 并赋值 `b.b` / `b.c`；type3 在 pc1852–1880 直接切回 Canvas，不保存文字。底部软键标签和触发命令现在使用相同映射。

### 桌面 SDL2 中文提交路径（2026-10-21）

本轮把桌面原生 SDL2 窗口的“编辑框 + 输入法提交”整条链路走通；此前只有 headless 回放与独立 Android 实例的证据。原 JAR 未修改（运行前后 SHA-256 均为 `bfa87c2046aa0d2b3847521ffdd34baf27a3de252b07031830d3b966eb2e66d2`），原手机仍未复测。

- 先解释桌面停住的原因：SDL2 端口在带 POSIX 网络支持构建时无条件安装真实网络（`src/port/posix/nj_port_sdl2.c:1943-1944`），`src/runner/nj_run.c` 没有关闭网络的参数，游戏一直卡在“流金网络/接受数据发送”闪屏重试真实 DNS 与连接；headless 端口没有 HTTP 实现（`src/midp/nj_lib_http.c:412,460` 的 `this build has no HTTP support; the port must supply it`），所以直接失败并继续。回放时给 SDL 进程设置本机回环代理，对所有请求立即返回 503（`Content-Length: 0`），并用 `http_proxy`/`https_proxy`/`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`all_proxy` 与空的 `NO_PROXY`/`no_proxy` 指向它；5 个 `POST /center/GameComm`（xy.liujin.cn:8000、xy.ljsy.net:8000 两次、117.135.140.227:8000 两次）约 1.5 秒内失败，流程与离线一致。
- 截屏：`--dump-frames` 只在 headless 端口实现（`src/port/posix/nj_port_headless.c:59,786`），SDL 窗口改用 `xdotool` 取窗口 ID 后 `import -window` 截屏，并套 `timeout -k 2 8` 防止 ImageMagick 卡住。
- 页面推进用模板匹配（180×320 下采样、通道差≥48、差异比<0.05）代替固定等待：闪屏 → 标题+“请检查设备网络连接” → F1（左软键）打开《注册协议》 → 再 F1 进入《游戏注册》表单 → 表单上 F1 提交会弹“用户名和密码长度至少要四位!” → 在账号框上按 fire/Return 打开 MIDP 全屏编辑器（标题“游戏账号”，软键“确定/返回”） → F1 确定回到表单。
- 注入方式：`.local-tools/debug-runs/uc-ime-20261021/text_inject.c` 用 `LD_PRELOAD` 包装 `SDL_PollEvent`；当真实轮询返回 0、尚未注入、`NJ_TEXT_FILE` 文件存在且 `SDL_IsTextInputActive()` 为真时，删除标志并返回一条携带 UTF-8 `中文ABC` 的 `SDL_TEXTINPUT`，同时打印 `TEXT_INJECT tick=<毫秒> text=中文ABC`。它模拟“输入法已提交”的事件，不是操作系统输入法组合（无候选窗、无 preedit）。
- 证据（均为本轮 `git archive` 干净构建的 `build/nj2me`，SHA-256 `a821b5977760ff2f9de6fb9f8cce3bded06c242444000ce7afde3676642e5c33`；shim SHA-256 `275094a72d697500e939fe82398142b1f99a6683cb355a671c1315de3aabf884`；三组运行退出码 0、原 JAR 哈希不变）：
  - `xy-tpl6`：44.0 秒进入注册页，日志 `TEXT_INJECT tick=44159`，Return 后[编辑器](../../.local-tools/debug-runs/uc-ime-20261021/xy-tpl6/90-return.png)标题“游戏账号”、内容 `中文ABC`（中文与 ASCII 均正确渲染），底部“确定/返回”，总 49.06 秒。
  - `xy-ime-final1`：日志 `TEXT_INJECT tick=44168`，确定后[表单字段](../../.local-tools/debug-runs/uc-ime-20261021/xy-ime-final1/91-field-filled.png)“游戏账号”显示 `中文ABC`，[最终画面](../../.local-tools/debug-runs/uc-ime-20261021/xy-ime-final1/99-final.png)保持。
  - `xy-ime-final2`：日志 `TEXT_INJECT tick=38694`，[编辑器](../../.local-tools/debug-runs/uc-ime-20261021/xy-ime-final2/90-editor.png)显示 `中文ABC`。
  - 每组目录的 `manifest.json`、`runtime.log` 记录 argv、二进制与 shim 哈希、时间戳、代理请求明细。
- 边界：这是合成提交，证明的是端口“SDL 文本提交 → MIDP 可编辑控件 → 中文渲染/回填”链路，不等同于真实拼音输入法；`SDL_TEXTEDITING` 预编辑仍未拼进控件值（`src/port/posix/nj_port_sdl2.c:1128-1130` 只置 `ime_composing`），没有候选窗；SDL 复现里合成指针点击 (117,44) 未打开编辑器，只有 fire/Return 能打开；未复测 Android、未提交注册、未登录、未验证在线游玩。
