# MPEG-4 runtime replacement provenance, 2026-11-12

The known FFmpeg-derived transform, coefficient loops, motion/predictor paths, packet parsing, and cache-clearing logic in `src/midp/nj_m4v.c` have been removed. Reconstruction uses original H.263 equation-based code; MPEG-4-specific syntax and prediction use the MIT-licensed source pinned below. The original VOL framing and provider/allocation integration remain project code. This note records source evidence and changes; it is not a legal opinion or a separate-person clean-room claim. Repository-wide licensing is reviewed separately.

## Primary source and derivation

The source used for the replacements is **ITU-T Recommendation H.263 (01/2005)**:

- Official record: <https://www.itu.int/rec/T-REC-H.263-200501-I/en>
- Official freely available PDF: <https://www.itu.int/rec/dologin_pub.asp?lang=e&id=T-REC-H.263-200501-I!!PDF-E&type=items>
- SHA-256 of the retrieved PDF: `9dc7e2528fa13ac9d3b6669996b053f6cea7897b5e1ecdd46a253e858ffd2c45`.

The PDF was consulted as a specification and is not added to the repository. No external decoder source or butterfly arithmetic was used for these three equation-based routines. MPEG-4-specific routines use the separately attributed MIT source below. The old code was inspected to identify the affected interface and provenance; this was not a separate-person clean-room process. The implementation is independently expressed from the equations, and this note does not provide a legal clearance opinion.

The inverse transform follows section 6.2.4's separable orthonormal cosine equation. Its stored basis is generated by

```
B[u,x] = floor(2^20 * C(u)/2 * cos(pi*(2*x+1)*u/16) + 0.5)
C(0) = 1/sqrt(2); C(u) = 1 otherwise
```

Two matrix products use signed 64-bit accumulators. Rounding occurs once at the final 40-bit scale; division explicitly handles negative values without relying on an arithmetic right shift. With the specified 12-bit input coefficients, accumulator magnitude is below `2^56`. A DC-only block uses the exact rational `DC/8` rather than an approximate basis product. Intra pixels are clipped to 0..255 and receive no extra 128 bias (section 6.3). `nj_m4v_idct` produces a residual; `nj_m4v_idct_put` produces clipped intra samples.

The old seven-weight SimpleIDCT butterfly, its row/column shifts, and unsigned wraparound arithmetic were removed. The existing shared 12-bit matrix was evaluated as a candidate but was not retained: rounding between passes failed the section's Annex A accuracy test (peak error 2, overall MSE approximately 0.20, versus limits 1 and 0.02). The new local 20-bit matrix leaves the shared H.263 implementation untouched.

Half-pixel interpolation follows section 6.1.2, Figure 13. One fractional axis averages two samples with bias `1 - RCONTROL`; two fractional axes average four with bias `2 - RCONTROL`. Non-integral chroma quarter-pixels map to the half-pixel position using Table 18. Out-of-picture samples repeat the boundary sample, as in Annex D.1. Negative vector coordinates use explicit floor division. The new implementation accumulates the required sample rectangle instead of reproducing a decoder's four branch implementation.

The sum of four luma vectors is converted to one chroma half-pixel vector using Annex F.2, Table F.1. Of sixteen fractional positions, 0..2 map to zero, 3..13 map to one half-pixel, and 14..15 map to one pixel. The implementation uses these intervals rather than copying a lookup table.

## Validation and the changed assertion contract

`tests/private/test_m4v_equations.c` is an independent numerical test. It uses the Annex A pseudorandom sequence, double-precision forward and inverse cosine sums, coefficient clipping, and all six 10,000-block datasets (three value ranges with both signs). It checks all specified per-pixel and aggregate peak, mean, and mean-square limits, and the all-zero case. It also checks 473,344 interpolation samples over positive/negative vectors, both fractional coordinate scales, both rounding controls, and edges; and 8,193 chroma vectors against Table F.1.

The old MPEG-4 integration assertions required exact FFmpeg SimpleIDCT hashes. Exact agreement with a particular integer butterfly is incompatible with replacing that algorithm with an independently expressed standards-accurate transform. The updated tests compare every pixel with independently decoded references:

- Every YUV sample in the four-frame I/P/I/P sequence, six-frame sliced movie, and four-frame AC-prediction movie differs by at most **one** 8-bit level. Each plane's MSE must be at most **0.40**. The measured maximum is **0.376953**, on the AC-prediction fixture; this is an empirical short-clip regression bound, **not** an Annex A limit or a guarantee for arbitrary prediction-chain lengths.
- Provider and Java Player RGB565 frames differ by at most **one code value per 5/6-bit channel**, with at most **2%** of pixels changed.
- Existing parser, vector, scan, coefficient, end-of-stream, allocation cleanup, picture count, geometry, and bit-consumption assertions remain. The sequence now compares all four frames rather than only the two P pictures. Named-coordinate comparisons permit one level.

`tests/private/make_m4v_reference.py` decodes the existing encoded fixtures with the external FFmpeg executable (`-threads 1 -idct simple -flags +bitexact`, timestamp passthrough, raw YUV420p), then zlib-compresses the pixel arrays into `tests/private/m4v_reference_data.h`. The generated header records the FFmpeg version and input SHA-256 values. It contains decoded test pixels, not decoder implementation. Normal tests use the existing built-in inflater and need no FFmpeg installation. `tests/private/m4v_reference.h` compares those pixels, including the same YUV-to-RGB565 conversion used by the runtime.

After all runtime replacements and parser regressions, the final normal focused suite passed **5/5** tests in **0.20 s** (`test_m4v`: 135 checks, `test_lib`: 1,790 checks). ASan/UBSan passed the same **5/5** in **0.85 s**, without sanitizer diagnostics. Across the six Annex A datasets, the maximum peak error was **1**, worst per-pixel MSE **0.0005**, worst overall MSE **0.0001109**, worst absolute per-pixel mean **0.0004**, and worst absolute overall mean **0.0000141**. Interpolation and chroma-vector checks had zero mismatches. The sanitizer build emitted an existing unrelated `strchr` warning in `src/midp/nj_lib_socket.c:151`.

The C adaptations differ structurally from the removed loops:

- Coefficient parsing produces an explicit `{last, run, signed level}` event. Intra/inter decoding shares one checked scan walk; LAST is never encoded as the former `run + 192` sentinel. Three escape forms follow `texture.rs` sections 7.4.1.2/7.4.1.3, including explicit markers and prohibited levels 0/-2048. Scalar inverse quantization is a separate H.263 6.2.1 equation and clamps reconstructed AC values to [-2048,2047].
- Motion differences follow `motion.rs`: `sign * ((abs(code)-1) * 2^(f_code-1) + residual + 1)`, then signed-interval wrap. Figure 7-34 candidate coordinates and availability are derived from `mv_predictor_grid.rs`. Frame drivers pass an absolute packet-start macroblock index rather than first/second-row special cases.
- Packet parsing consumes bounded stuffing, marker, macroblock number, quantizer and extension flag into a local cursor. Malformed syntax and unsupported extensions leave the public cursor/quantizer unchanged. Zero packet quantizers are refused. Header extensions remain unsupported, as before.
- AC/DC neighbours are queried by geometric location and whether their macroblock precedes packet start. Quantized predictor slots record validity/quantizer with their first row/column. Non-intra blocks invalidate their own slots; beginning a packet changes one index. The former reference-derived clearing bands have been removed. Direction, tie and rescaling rules adapt `predictor.rs` and `neighbour.rs`.
- P-macroblock grammar adapts `macroblock.rs`; common VOP grammar adapts `vop.rs`. Three scan-order arrays are inverse maps of `scan.rs` Figure 7-4; all 192 entries equal their previous numeric values.

The legacy public `nj_m4v_escape1/2/3` helper numeric contracts are deliberately preserved through compatibility wrappers. The actual decoder uses raw quantized coefficient events. A zero motion VLC continues to return the supplied predictor unchanged, including the old helper's out-of-range test input. No runtime native/savestate flags are altered by this work.

## Retained original framing and optional syntax

History inspection distinguishes syntax facts from function transcriptions. `fd02094` introduced the project's C VOL bit reader; `45f0b79` records DC/MCBPC and field-position facts; `de7aa2c` records optional complexity bit-count flags. The known expressive coefficient/motion/transform transcriptions in `9ae1e0f` and `a7c597b` were the replacement targets. The original VOL reader is retained; following encoded field order does not by itself make its project-specific C control flow an imported decoder function.

The MIT upstream rejects complexity-enabled VOLs. To preserve existing support, this project now expresses optional complexity fields using descriptors `(picture class, encoded width)` and four flag groups, with marker validation. The VOP reader uses a bounded metadata field walk. Those field facts came from the existing supported grammar/history; they have not been independently certified against a newly obtained ISO edition. No ISO licensing gateway terms were accepted. The new expression is project code, not an unattributed port or an assertion of a separate clean-room process.

Shared VLC/DC/scaler/escape tables are sourced and generated separately under `docs/M4V_TABLE_PROVENANCE.md`; their audit does not substitute for the runtime replacements documented here.

## Additional parser regressions

`tests/private/m4v_syntax_cases.h` adds:

- **1,836** combinations covering all 102 intra symbols, both signs, direct/type-1/type-2 events, and three scans, including a following terminal event for non-LAST symbols.
- Each of **22** optional complexity flags, required-marker failure, and exact I/P complexity payload consumption before quantizer/MV fields.
- Explicit escape signed extremes, reserved zero/-2048, nonzero scan origin, marker and truncation refusals.
- Packet bad stuffing, zero QP and unsupported extension refusals with cursor/quantizer preservation.
- **4,096** deterministic malformed event/VOL/VOP inputs with coefficient guards and cursor bounds.

Existing full-pixel sliced/AC-prediction sequences exercise packet availability and changing predictors. These regression checks complement the independent normative numerical test; they do not claim a complete MPEG-4 conformance test suite.
