# The -Os rasteriser: where the in-world time goes, and two specialisations (2026-11-02)

The APK is built with clang `-Os` (`tools/build_android.sh`, `--opt` defaults to `s`), while
every raster optimisation so far was scored on the desktop `-O3` build.  This note measures the
`-Os` in-world frame, finds the loop that actually costs the time, and takes two bit-exact
specialisations of it: -0.95% alone (the sampler half) and -2.27% together with the
span-constant branch half, both against the pristine `-Os` build.  The same source at `-O3`
comes out 0.3% faster, so the desktop keeps its behaviour.

## Measurement setup

Worktree `r5-m3g` at `331686f`; saved in-world state `.local-tools/mc051/world.state`, 240x320,
`--port headless --heap 32 --fps 0 --run-frames 1200`, one pinned core (quietest sampled from
`/proc/stat`), user CPU from bash `time`.  Builds:

    build-os        clang -Os -DNDEBUG          (the reference, A)
    build-clang-o3  clang -O3 -DNDEBUG
    build           gcc   -O3 -DNDEBUG          (desktop Release)
    build-os-pg     clang -Os -DNDEBUG -pg -g -fno-pie + -pg -no-pie link

Desktop timing of the pristine tree (1200 frames, user CPU):

| build | s | vs -Os |
|---|---|---|
| clang -Os | 3.283 | - |
| clang -O3 | 3.129 | -4.7% |
| gcc -O3 | 3.105 | -5.7% |

So `-Os` pays about 4.7% over `-O3`; the bar for this task was a 2% win over pristine `-Os`.

## Profile: the flat_texargb span loop is 20% of the run

`clang -Os -pg`, 1200 frames (2.62 s of samples).  `sw_tri()` is inlined into `jr_emit()`, so
its flat self time is the whole rasteriser:

| function | self s | % | calls |
|---|---|---|---|
| jr_emit (contains inlined sw_tri) | 1.16 | 44.3 | 10,754,632 |
| jr_fetch (contains inlined jr_vertex) | 0.25 | 9.5 | 25,457,092 |
| nj_interp_run | 0.24 | 9.2 | 13,992 |
| jr_project | 0.23 | 8.6 | 25,740,964 |
| nj_crc_update (snapshot load, not frame work) | 0.19 | 7.3 | 2 |
| sw_fog | 0.11 | 4.2 | 36,596,160 |
| jr_triangle_v | 0.05 | 1.9 | 12,728,546 |
| jr_strip | 0.05 | 1.9 | 6,364,273 |

Summing the `-l` line profile by source range splits `jr_emit` further:

| range | -Os s | -Os % | -O3 s |
|---|---|---|---|
| flat_texargb span loop | 0.53 | 20.1 | 0.49 |
| sw_tri setup (bbox, edges, ceil/floor) | 0.26 | 9.8 | 0.21 |
| jr_project | 0.22 | 8.3 | 0.22 |
| inlined sw_near_texel | 0.14 | 5.3 | 0.15 |
| flat_opaque / flat_tex565 / generic loops | 0.02 | 0.8 | 0.03 |

A temporary pixel census (not committed) confirmed which loop this title uses: 43.7k
`flat_texargb` pixels per frame in 9.6k spans (4.6 px/span), and the `flat_opaque`,
`flat_tex565` and `generic` loops get **zero** pixels.  The same census measured the
span-constant flags of every `flat_texargb` span:

| flag | share of pixels |
|---|---|
| both wraps CLAMP (the affine path) | 77% |
| `fog_here == 1` (no fog work) | 74% |
| `tint` on | 90% |
| `!blend_alpha` (no alpha blend) | 78% |
| `dtest` + `dwrite` on | ~85% |
| dominant combination (clamp, no fog, tint, no blend, dtest+dwrite) | **58%** |

`jr_project`'s 8.6% is a `-pg` artefact: the 25.7M calls are counted in both builds, but at
`-O3` the function is inlined into the caller so its mcount calls disappear.  Forcing it inline
at `-Os` with `always_inline` made the binary 2.5% **slower** (measured, 3 rounds); the function
stays out of line.

## Change 1: the clamp-specialised span loop (-0.95%)

`sw_near_texel()` is inlined once per pixel and, for the general case, dispatches on
`sw->wrap_s`/`sw->wrap_t`, reloads `sw->tex_w`, `sw->tex_h`, `sw->tex_bpp` and converts the two
integer sizes to float, every pixel.  For a CLAMP-wrapped texture none of that moves inside a
triangle.  The `flat_texargb` branch now carries a second copy of the span loop for the
`!st_outer` case:

    if (!st_outer) {
        const nj_u1 *texp = sw->tex;
        const int texw = sw->tex_w, texh = sw->tex_h;
        const int texbpp = sw->tex_bpp;
        const float texwf = (float)texw, texhf = (float)texh;
        const int athresh = sw->athresh;

        for (...) {  /* sampler inlined with the fields above, no wrap dispatch */ }
    } else
        for (...) {  /* the original body, sw_near_texel() as before */ }

The specialised sampler keeps `sw_near_texel()`'s float expressions verbatim (same order, same
constants), so it selects the same texel bit for bit:

    fs = ph * cp;  fs = fs < 0.0f ? 0.0f : (fs > 1.0f ? 1.0f : fs);   /* wrap_s == 240 */
    uu = (int)(fs * texwf);  ...  tp = texp + (v * texw + u) * texbpp;

## Change 2: the dominant-case span loop (-1.3% on top)

Inside the clamp branch, a third copy of the loop is selected when the span-constant flags are
the dominant combination: `fog_here == 1 && tint && !blend_alpha && dtest && dwrite && awrite &&
bpp4`.  Under those guards the per-pixel branches are dead and are removed, not approximated:

* the `blend_alpha && ta <= 1u` early-out and the `blend_alpha && (ta < 255u || blend_other)`
  blend tail (dead: no blend),
* the `if (tint)` wrapper (the three `(c * fc) / 255u` multiply exactly as before),
* the whole fog block (`fog_here == 1` means neither the constant-fog nor the per-pixel path can
  run),
* `if (dtest && key <= z[o])` becomes `if (key <= z[o])`, `if (dwrite) z[o] = key` becomes an
  unconditional store, and the `if (!awrite)` fix-up disappears,
* `ta = bpp4 ? tp[3] : 255u` becomes `tp[3]` (the guard makes `bpp4` true).

Everything else - edge stepping, the depth key, `1.0f / pg`, the tint arithmetic, the final
`(ta << 24) | ...` pack and `memcpy` - is copied verbatim from the loop it replaces.

## Correctness

The two loops are textual copies of the original with the guarded branches removed; no float
expression was reassociated, no arithmetic was replaced, no pixel was moved.  Checks:

* `./build/test_m3g` (Release): `865 checks, 0 failures`, PASS.
* same under ASan+UBSan (`-DCMAKE_BUILD_TYPE=Debug -DNJ_SANITIZE=ON`, `ASAN_OPTIONS=detect_leaks=0`):
  `865 checks, 0 failures`, PASS, no sanitizer report.
* `tools/check_m3gdemo.sh`: `M3G checks=148 failures=0`, PASS.
* `tools/check_no_statics.sh`: OK (75 object files, only read-only tables).
* `ctest --test-dir build`: 137/137 passed (a fresh worktree registers 137 of the main tree's
  140; the three `test_port_*` need port fixtures that only the main tree has).
* Frame dumps of the saved state (61 frames, every 5th dumped = 12 frames), candidate vs four
  interleaved pristine runs: every candidate frame is **pixel-identical (0 differing pixels)** to
  at least one pristine run.  The only differences between runs are the title's wall-clock
  cloud/light animation phase (a whole-scene lighting variant, up to 20k pixels on one frame
  boundary, and the usual 0-9 pixel cloud-band jitter), which baseline-vs-baseline runs show
  just as much.

## Ruled out

* `always_inline` on `jr_project`: measured 2.5% slower at `-Os` (register pressure and i-cache
  beat the call); the `-pg` profile that suggested it was mcount inflation.
* Optimising the generic span loop: this title never enters it (zero pixels in the census).
* Hoisting loop-invariant `sw->` fields into `sw_tri()` locals outside the specialised loops:
  clang already keeps what fits in registers; the win came from removing the wrap dispatch and
  the branches, not from moving loads.

## Android relevance

`tools/build_android.sh` builds all ABIs with clang `-Os`, so these loops are what the APK
executes.  The change is bit-exact, adds no state (no statics, no new fields), and only touches
`src/midp/nj_lib_m3g.c`; the code is plain C99 with no architecture-specific intrinsics, and the
same source at `-O3` is 0.3% faster on the desktop, so the desktop build does not regress.
