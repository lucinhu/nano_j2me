# 软件绘制、JIT 与 GPU 性能实测 · 2026-11-26

基线为 `b178c025a3058c126d65ffa32657e319f9eba48b`。桌面使用 Core Ultra 9 275HX 和 GCC 16.2.1。各组交替运行两个版本，统计相同工作量的耗时中位数。游戏画面、选择的渲染模式和输入序列在同组中一致。

## 纯软件绘制

下表是五对 `-O3` 测试的中位数，单位为纳秒／源像素。高清测试同时绘制逻辑画面与物理画面，校验覆盖两者及行尾填充。28 个用例的输出校验值逐项吻合。

| 绘制操作 | 基线 | 优化后 | 耗时降低 |
| --- | ---: | ---: | ---: |
| 37×29 混合透明度 ARGB 精灵 | 3.611 | 1.106 | 69.4% |
| 同一精灵旋转 90° | 1.699 | 1.176 | 30.7% |
| 37×29 原样复制并旋转 90° | 0.234 | 0.193 | 17.2% |
| 240×320 不透明背景，3× 最近邻 | 1.656 | 1.112 | 32.9% |
| 混合透明度精灵，4× 最近邻并旋转 | 8.311 | 3.916 | 52.9% |
| 240×320 双色斜边，3× 像素画清晰 | 9.799 | 6.048 | 38.3% |
| 240×320 细碎纹理，4× 像素画清晰 | 9.632 | 4.653 | 51.7% |
| 半透明精灵，4× 像素画清晰并旋转 | 19.295 | 16.594 | 14.0% |

ARGB 混合把两个颜色通道装入独立的 16 位通道，一次计算两个通道的覆盖和舍入。旋转精灵按实测 alpha 成组写入，潜在重叠视图按原有的逐像素顺序读取。高清背景扫描每行的 alpha，再成行扩展不透明纹素。「像素画清晰」把相邻平坦单元的首行一并复制到后续行，斜边和半透明单元继续使用各自的物理采样点。RGB565 混合、蒙版、XOR 与填色对照的耗时变化介于减少 0.7% 和增加 2.5% 之间。

用相同版本的基准程序分别链接基线和优化后的绘图实现。以下命令在仓库根目录运行。两份可执行文件固定在同一个核，并交替执行。

```sh
cc -std=c99 -O3 -Iinclude tools/bench_gfx.c src/gfx/nj_gfx.c tests/stub_font.c -lm -o /tmp/nj-bench-gfx
for mode in --alpha --hd --assets; do taskset -c 2 /tmp/nj-bench-gfx "$mode"; done
```

另用两款零售游戏验证整段运行。固定游戏时钟、解释执行、240×320 逻辑尺寸、3× 像素画清晰和按键序列，每轮使用新的 RMS 和文件目录。下表为关闭截图后五对运行的实际耗时中位数，游戏设置为 30 fps。另行每 90 帧取样，22 张 720×960 画面逐字节相同。

| 游戏 | 帧数 | 基线 | 优化后 | 耗时降低 |
| --- | ---: | ---: | ---: | ---: |
| 3D版田园物语 | 1,080 | 2.226 s | 1.952 s | 12.3% |
| 恋爱物语－我的机器女友 | 900 | 1.611 s | 1.285 s | 20.3% |

两版分别执行了相同的 55,689 和 22,084 个绘图调用，Java 字节码计数分别为 86,787,896 与 101,497,990。

## JIT

x86-64 与 AArch64 在直线代码内合并已执行字节码的计数，到可能产生异常的操作、跳转和出口前结算。缓存中刚被淘汰的热点需要再次积累热度才能进入，延迟占用方法热度表原有的 16 位单元。回归覆盖提前退出、异常前的计数、调度预算、代码容量上限和持续热点再次入选。

使用原版 MinecraftJ2ME PE 0.6.1，种子 `12345`，固定 x86-64 CPU 核，计时 `Gen.generate` 生成 256 个区块的过程。三对交替运行结果如下。

| 指标 | 基线 JIT | 优化后 JIT |
| --- | ---: | ---: |
| 生成耗时中位数 | 15.982 s | 14.417 s |
| 成功编译次数 | 616,519 | 180,847 |
| 已编译块淘汰次数 | 616,468 | 180,796 |
| 原生执行的 Java 字节码数 | 3,440,208,304 | 3,428,581,102 |
| JIT 元数据 | 14,504 B | 14,504 B |

另用同一优化后二进制和相同种子交替运行三对，解释器用时中位数 14.303 秒，JIT 为 14.530 秒，解释器在这个生成场景仍快约 1.6%。

新旧 JIT 和解释器的 256 对区块哈希逐一相同，世界汇总为 `a893a062 / c77a1b93`，出生点为 `(161, 64, 111)`。单独测量计数合并时，x86-64 的局部变量、常量、字段、数组、混合运算及分支内核达到原速度的 1.48–2.13 倍，另外两个字节数组和矩阵内核与基线接近。AArch64 在 QEMU 下通过运行时及指令生成测试。用 Android NDK r30 编译同一套指令生成测试，在 API 36 x86-64 模拟器的 arm64 转译环境中又运行了 4,456 次生成的 ARM64 代码，共通过 2,315,061 项断言。Android 性能试用包通过 `NJ_ANDROID_JIT=1` 启用 JIT。

复现工具为 [Minecraft 生成基准](../../tools/bench_minecraft_gen.c) 与 [JIT 内核基准](../../tests/test_jit_perf.c)。

```sh
bench_minecraft_gen path/to/original.jar 12345 --jit-mode execute
```

## GLES2

GLES2 读回颜色时按目标矩形一次检查尺寸和格式，再按行写入 RGB565、RGB888 或 ARGB8888。三角形绘制的颜色和深度仍在两次读回都成功后提交。对于带额外像素间距的表面，继续按其声明的间距写入。

在 RTX 5080 Laptop（驱动 620.73.04）上运行 `test_gfx_gles2 --bench-readback`。同一份基准程序分别链接两个版本的库，交替测试三对。每轮预热 16 次，计时 512 次完整的 480×640 同步填色与回读。目标图像起点偏移 17 字节，行末留 7 字节填充。测试校验提交次数、全部最终像素以及每行填充和缓冲区两端的字节。

| 目标格式 | 基线用时 | 优化后用时 | 吞吐量倍数 |
| --- | ---: | ---: | ---: |
| RGB565 | 400 ms | 160 ms | 2.50× |
| RGB888 | 372 ms | 140 ms | 2.66× |
| ARGB8888 | 371 ms | 148 ms | 2.51× |

## Vulkan

小端设备读到 RGBA8 纹理时，内存排列与着色器读取的 32 位纹素相同，可以一次复制整段。每个绘图包重新读取纹理内容，RGB 纹理继续显式打包。测试每次修改同一未对齐缓冲区中的一个纹素，再验证屏幕上实际采到的新颜色。

以下为完整同步绘图调用，单位为毫秒。每轮预热 5 次、记录 50 次，表中取三个交替轮次的中位数。绘制区域较小，以便看清上传开销。

| GPU | 可变 RGBA8 纹理 | 基线 | 优化后 |
| --- | --- | ---: | ---: |
| Intel ARL，Mesa 26.3.1 | 256² | 0.149 | 0.130 |
| Intel ARL，Mesa 26.3.1 | 1024² | 0.788 | 0.350 |
| RTX 5080 Laptop，620.73.04 | 256² | 0.057 | 0.047 |
| RTX 5080 Laptop，620.73.04 | 1024² | 0.403 | 0.219 |

启用 Vulkan 后执行 `test_gfx_vulkan --bench-atlas`。设备可通过 `VK_DRIVER_FILES` 选择。常规测试同时覆盖 RGB、裁剪、深度、混合及回退。

## 3D 游戏和整机回归

在 RTX 5080 Laptop 上分别使用 GLES2 与 Vulkan 回放《毁灭战士3》。旧版和新版都固定游戏时钟、输入和解释器，连续绘制 250 帧。每个后端提交 9,873 个高清绘图包、4,229,899 个三角形。每个后端取样的 31 张 480×640 画面均与该后端的旧版逐字节一致。

纯软件构建通过 222/222 项 CTest，启用 JIT、GLES2、Vulkan 与 FSR2 的构建通过 236/236 项。Android arm64-v8a 安装包在 API 36 模拟器中运行同一个 MIDlet，稳定后截取的色块和斜边与旧包逐像素一致。
